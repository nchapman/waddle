### /handoff/pull k=1 fallback serves a fired machine's escrowed master secret to any shared-secret holder
**`concierge/src/index.ts:601`** — found by correctness, security, robustness
Still valid and unchanged by this diff. When handoff.release(instance) returns notFound, the handler computes handoff.singleOpenWindow() for a caller whose name matches neither USER_NAME_RE nor STANDBY_NAME_RE and calls handoff.release(open), returning `{ credential: via.cred, instance: open }` for a machine the caller never named (lines 594-601). Auth is requireSecret — the single fleet-wide CONCIERGE_SHARED_SECRET that every machine is provisioned with (STANDBY_SECRETS includes it) and that server/src/concierge.ts still sends as the machine handshake bearer. The escrowed credential is the opaque bag `{ secret, schedules[], snapshot? }` (the user's master secret plus a sealed whole-machine snapshot). Consequence: any shared-secret holder can POST /handoff/pull with an allowed non-user name (e.g. the baked default "waddle") during any machine's ~3-minute release window and receive that machine's master secret and snapshot, without knowing or naming it — contradicting the route's own guarantee that a boot the concierge did not deploy gets 404.

**Fix**: Bind the fallback to the caller identity rather than the shared key alone (e.g. only serve when the puller presents the concierge-minted session/instance it was deployed for), or drop the fallback now that machines adopt their name from /handshake before the pull.

The diff replaced the reachability probe (`await fetch(`${ENCLAVE_URL}/health`, …)`; only an unreachable enclave auto-woke) with `if (!DEV && !discoveryTriedRef.current) void wakeCore(…)`, which runs for ANY exception from verifyEnclave/the attested /health — including config-repo fetch failures and attestation failures. ### k=1 fallback consumes the one-shot fire for any allowed shared-secret caller
**`concierge/src/index.ts:593`** — found by robustness
Still valid. The fallback calls handoff.release(open) (line 597), whose success path does `firedAt.delete(instance)` (handoff.ts release — one-shot per fire). The caller is authenticated only as *some* allowed instance holding the fleet-wide shared secret; nothing verifies it is the fire's intended waiter. A stray/duplicate pull, or a second secret-holding machine carrying an allowed name with no fire, therefore receives the fired row's credential and permanently consumes its window; the intended boot then gets 404 and cannot run its schedule until the next fire.

**Fix**: Make the fallback non-consuming on an unsuccessful/duplicate attempt (do not delete the fire until the intended boot confirms), and/or require a pull marker minted at deploy time so a duplicate request cannot burn the window.

### Transient handshake failure is indistinguishable from an identity refusal and now leaves the machine with no concierge session
**`server/src/index.ts:322`** — found by robustness
handshakeConcierge() delegates to post(), which returns null for every failure — a 409 (as the new concierge branch returns on presented_instance mismatch), a 5xx, and a network error/timeout all collapse to `false`. The new line `if (bb?.token && instance) return (await handshakeConcierge(bb.token, instance)) ? bb.token : undefined;` therefore treats a transient blip as "wrong machine" and skips the shared-secret fallback entirely for every live unlock that sends a presented name (the client always does; session.ts:71). The result: bearer is undefined, `renewIdleStop()` (line 324) is skipped and conciergeActive() stays false, so the machine can arm no stop/wake rows and its exit deathFlare() cannot run for the session — billing then depends solely on the claim-grace row the comment invokes. There is no retry and no distinction in the logs between a network failure and a deliberate 409.

**Fix**: Distinguish transport/5xx failures from a definitive 409 in handshakeConcierge (or in the caller) and retry/log them separately, so a transient concierge error does not silently present itself as an identity mismatch that disables delegation for the whole session.
