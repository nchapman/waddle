### New JWT-accepting /handshake branch and k=1 /handoff/pull fallback ship with no test protection
**`concierge/src/index.ts:596`** — found by correctness, security, tests
The reorder makes `legacyCaller` = any string that does not match USER_NAME_RE or STANDBY_NAME_RE, and then skips `allowedInstance` entirely (`if (!legacyCaller && !allowedInstance(instance))`). Combined with the config change dropping `CONCIERGE_ALLOWED_INSTANCES` (default now ""), the name gate on this route is effectively dead: a caller can present any arbitrary name (the baked "unadopted", or literally any junk string) and be classified legacy. The route then runs `handoff.release(instance)` -> notFound -> `handoff.singleOpenWindow()` (concierge/src/handoff.ts:107), which returns *the one open fire window's row regardless of who is asking*, and returns `{ credential, instance }`. That credential bag is the instance's master secret plus an optional sealed whole-machine snapshot (server/src/concierge.ts PulledCredential). The only authentication is `requireSecret` against the fleet-wide `CONCIERGE_TOKEN` that every waddle machine holds (config/tinfoil-config.yml secrets), so any one machine compromise can exfiltrate a peer instance's master secret / sealed state. Previously the trigger was restricted to an operator-allowlisted name ("waddle"), which was no real barrier either, but this diff removes the last gating on the path and widens admission to every input string, and the comment's claim that "that fire's boot is this puller" is not enforced anywhere.

**Fix**: Add route-level tests (a Fastify inject harness) covering: sentinel pull with the shared secret resolves via singleOpenWindow; a user/standby-shaped but unknown name is 403; bad secret is 401 before any name work; and the /handshake secret tier's accept/refuse split.
