### Default-empty ALLOWED plus machine default "unadopted" makes the pre-adoption shared-secret paths 403 — wake-autonomy pull and locked-boot reaper break
**`concierge/src/index.ts:70`** — found by correctness, security, robustness
ALLOWED defaults to "" (`CONCIERGE_ALLOWED_INSTANCES ?? ""`, concierge/src/index.ts:68-73) and a fresh machine's INSTANCE is the sentinel "unadopted" (server/src/concierge.ts:32), which matches neither USER_NAME_RE nor STANDBY_NAME_RE in allowedInstance (index.ts:207-216). The /handoff/pull half is healed by the legacyCaller bypass (index.ts:588-597: a non-user/non-standby name skips allowedInstance and is served the single open fire window), but the /handshake secret-only branch still runs `const { instance } = req.body ?? {}; if (!allowedInstance(instance)) return reply.code(403)` (index.ts:500-507) on the same sentinel. So an identity-less machine's shared-secret handshake 403s and server/src/index.ts:938-946's locked-boot backstop never takes its `if (ok)` branch — no stop row is ever armed for that boot. The current tree only softens this by treating 403 as definitive (`if (res.status === 403) return false`, server/src/concierge.ts:120-126) instead of retrying it three times; the arming failure itself is unchanged, and on the 403 path nothing is logged by the caller (the `.then(ok => ...)` body is skipped), so the machine silently falls back to the platform clocks.

**Fix**: Give the secret tier the same sentinel exemption at /handshake that /handoff/pull now has (a legacyCaller-style bypass usable only by the shared-secret tier), or keep a configured bootstrap identity that allowedInstance accepts until the locked-boot path is re-keyed; and log the 403 case on the locked-boot caller so the degrade is visible.

On /handoff/pull, `legacyCaller` is any string that does not match USER_NAME_RE or STANDBY_NAME_RE (index.ts:584-598), and `if (!legacyCaller && !allowedInstance(instance))` skips the name gate entirely for such callers. ### Default-identity assertion pins the exact sentinel and is coupled to WADDLE_INSTANCE, without covering the fail-closed contract

(1) It binds the literal placeholder rather than the property that matters, so a rename breaks the test with no behavior change.
