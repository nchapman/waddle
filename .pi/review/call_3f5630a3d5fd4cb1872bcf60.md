### Default-empty ALLOWED plus machine default "unadopted" makes the pre-adoption shared-secret paths 403 — wake-autonomy pull and locked-boot reaper break
**`concierge/src/index.ts:70`** — found by correctness
This diff changes two defaults that must agree: ALLOWED now defaults to "" (index.ts:70, was "waddle") and the machine's pre-adoption identity is now "unadopted" (server/src/concierge.ts:31, was "waddle"; config/tinfoil-config.yml drops WADDLE_INSTANCE entirely, so production machines really start as "unadopted"). allowedInstance (index.ts:209-216) admits a name only if ALLOWED.has(name), or it is a pool-known standby, or a registry-known user name; "unadopted" matches none, and ALLOWED is now empty, so it fails. Every shared-secret (autonomous) route to the concierge is gated on allowedInstance and now refuses that name before any fallback: (1) POST /handoff/pull does `if (!allowedInstance(instance)) return 403` before its k=1 fallback (index.ts:~584 vs the `legacyCaller` block at ~594), and pullHandoff sends `instance: INSTANCE` = "unadopted" (server/src/concierge.ts:186-198). The k=1 fallback exists precisely for "a wake boot can't know its own name" — with the gate in front it is unreachable dead code, so a schedule-fired boot never obtains its escrowed credential and sits locked (server/src/index.ts:844 `pullHandoff()`). (2) The /handshake secret-only fallback also does `if (!allowedInstance(instance)) return 403` (index.ts:~505), so the locked-boot handshake at server/src/index.ts:930 with CONCIERGE_SHARED_SECRET fails, `conciergeActive()` stays false, `renewIdleStop()` is skipped, and a machine that unlocks from the wake credential (server/src/index.ts:909) can neither idle-stop nor be reaped — it burns compute forever. Same regression hits the dev loop: compose.dev.yaml still sets WADDLE_INSTANCE=waddle while `just concierge` (justfile:26) sets no CONCIERGE_ALLOWED_INSTANCES, so "waddle" now fails allowedInstance too.

**Fix**: Keep one name that the pre-adoption/legacy paths can present and that allowedInstance admits — e.g. retain a default ALLOWED entry (index.ts:70) matching the machine default, or add an explicit "unadopted"/legacy-pull allowance in allowedInstance (or a dedicated gate on /handoff/pull and the /handshake secret fallback) so the wake-boot credential pull and the locked-boot backstop handshake still resolve. If "unadopted" truly must be refused, remove the now-dead k=1 fallback and re-point the machine's pre-adoption identity at a name the concierge accepts.

### Defaulting the machine identity to "unadopted" silently breaks the locked-boot stop-backstop and the wake-boot credential pull
**`server/src/concierge.ts:31`** — found by robustness
This change makes the machine's pre-adoption identity "unadopted" (server/src/concierge.ts:31), removes the `WADDLE_INSTANCE: "waddle"` override (config/tinfoil-config.yml) and empties the concierge allowlist default (concierge/src/index.ts:70, `CONCIERGE_ALLOWED_INSTANCES ?? ""`), so the old bootstrap name "waddle" no longer exists anywhere. Every pre-unlock machine verb ships `instance: INSTANCE` (concierge.ts:65, `{ instance: INSTANCE, ...body }`) = "unadopted", and both concierge gates for that tier reject it: /handshake's shared-secret branch does `if (!allowedInstance(instance)) return reply.code(403)` (concierge/src/index.ts:492) and /handoff/pull does the same before its fallback. allowedInstance("unadopted") is false — not in ALLOWED (now empty), not USER_NAME_RE + users.known(), not STANDBY_NAME_RE. Two concrete regressions follow: (a) locked boot — server/src/index.ts:930 `void handshakeConcierge(process.env.CONCIERGE_SHARED_SECRET).then((ok) => { if (ok) renewIdleStop(); ... })`; the 403 makes handshakeConcierge treat it as transient, retry 3x and return false, so `renewIdleStop()` never runs and no stop row is armed — an abandoned locked machine is no longer reaped by the concierge and burns compute indefinitely; (b) wake boot — server/src/index.ts:844 `const cred = readWakeCredential() ??
