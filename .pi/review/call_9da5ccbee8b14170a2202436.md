### Default-empty ALLOWED plus machine default "unadopted" makes the pre-adoption shared-secret paths 403 — wake-autonomy pull and locked-boot reaper break
**`concierge/src/index.ts:70`** — found by security, robustness
ALLOWED defaults to "" (CONCIERGE_ALLOWED_INSTANCES ?? "", index.ts:68-73) and a fresh machine's identity is the sentinel "unadopted" (server/src/concierge.ts:32), which matches neither USER_NAME_RE nor STANDBY_NAME_RE in allowedInstance (index.ts:207-216). The /handoff/pull half is healed by the legacyCaller bypass (index.ts:588-589: a non-user/non-standby name skips allowedInstance and is served the single open fire window), but the /handshake secret-only branch still runs `if (!allowedInstance(instance)) return 403` (index.ts:502-503) with no sentinel exemption. server/src/index.ts:938-945 fires the locked-boot backstop as handshakeConcierge(CONCIERGE_SHARED_SECRET) with no presented name, so the body carries {instance:"unadopted"} → 403 → handshakeConcierge returns false (no retry, the 403 arm is definitive) → renewIdleStop() never runs and the locked machine can never arm its own stop row; likewise the autonomous wake boot's shared-secret handshake (server/src/index.ts:909-917) has no session, so writeTimer() short-circuits (server/src/concierge.ts:154) and the machine "burns forever" — the exact condition that comment names.

**Fix**: Give the secret tier the same sentinel exemption at /handshake that /handoff/pull now has (a legacyCaller-style bypass usable only by the shared-secret tier), or keep a configured bootstrap identity that allowedInstance accepts until the locked-boot path is re-keyed; and log the 403 on the locked-boot caller so the degrade is visible.

### Defaulting the machine identity to "unadopted" silently breaks the locked-boot stop-backstop and the wake-boot credential pull
**`server/src/concierge.ts:32`** — found by security, robustness
`let INSTANCE = process.env.WADDLE_INSTANCE ?? UNADOPTED` (concierge.ts:32) with WADDLE_INSTANCE unset in prod means every pre-unlock machine verb carries {instance:"unadopted"} (post(), concierge.ts:70-77). The wake-boot credential pull is healed: pullHandoff (concierge.ts:206-222) posts the sentinel but the concierge's legacyCaller fallback serves the single open fire window and returns the row's real name, which adoptInstance stores. The locked-boot backstop is not: renewIdleStop() returns early while INSTANCE === UNADOPTED (concierge.ts:165-167), and the only place that could adopt an identity on a locked boot — handshakeConcierge(CONCIERGE_SHARED_SECRET) at server/src/index.ts:938-945 — is refused 403 by the concierge's name gate, so the early return is never lifted and no stop row is ever armed.

**Fix**: Exempt the sentinel from allowedInstance for the shared-secret tier (mirroring the /handoff/pull legacyCaller handling) so the locked-boot handshake can mint and renewIdleStop() can arm the backstop, or drop the UNADOPTED early return in favour of the concrete failure path.

## 🟡 Suggestion

### /health demand_ms_ago serializes as null when demand was never marked
**`concierge/src/index.ts:305`** — found by security, robustness
pool.demandMsAgo() returns Infinity when lastDemandAt is null (concierge/src/pool.ts:247) and Infinity is emitted verbatim into the /health payload (index.ts:305). JSON.stringify(Infinity) is null, so the scale-to-0 diagnostic reaches probes as demand_ms_ago: null — indistinguishable from "unknown" and useless for the alerting this field exists for.

**Fix**: Serialise a sentinel explicitly (e.g. demand_ms_ago: Number.isFinite(v) ? v : -1, or a `never` boolean), and pin it in a test.

### Default-identity assertion pins the exact sentinel and is coupled to WADDLE_INSTANCE, without covering the fail-closed contract
**`server/src/concierge.test.ts:22`** — found by security, robustness, tests
Re-raise of the prior review finding — still valid. `assert.equal(currentInstance(), "unadopted")` (server/src/concierge.test.ts:22) hard-codes the sentinel, but INSTANCE = process.env.WADDLE_INSTANCE ?? UNADOPTED (server/src/concierge.ts:32). The dev-compose stack DOES export WADDLE_INSTANCE, so this test is green only in an env that happens to leave it unset — a false-negative that depends on the runner's environment rather than the code under test. It also asserts the identity string instead of the contract the string drives: nothing verifies that an un-adopted instance fails closed (renewIdleStop() is a no-op, writeTimer refuses pre-session), which is the behavior the sentinel exists to produce.

**Fix**: Assert the behavioural invariant instead of the literal: the first POST body carries the pre-adoption identity, a refused handshake adopts nothing, and a successful handshake/pull re-keys the body of subsequent verbs.
